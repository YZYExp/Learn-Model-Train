# 阅读路线与代码验证边界

本书按「先设计完整项目，再理解计算过程，随后阅读具体工具实现」组织。章节的稳定文件名是工程标识，不代表必须按文件名前缀阅读；在线目录和 `book.json` 决定阅读顺序。

## 工程主线

先读训练全景与顶层工程设计，明确任务输入、质量目标、数据来源、预算和验收。随后进入数据工程、训练方法与蒸馏，再读 HF、NeMo/Megatron 和 verl 三个工具链案例。它们分别用单机后训练、集群训练和在线 RL 展开实现细节，并非三种必须顺序安装的产品。

一次完整工程评审应能沿着「目标 → 指标 → 基线 → 误差 → 数据 → 模型与方法 → 训练计划 → 资源与成本 → 评测 → 发布」逐步追溯。某一环没有证据时，不应通过堆叠框架来掩盖。

## 原理主线

从训练循环进入张量计算章，跟踪 token、embedding、Q/K/V、注意力、MLP、logits、交叉熵、梯度与优化器。遇到显存或通信问题再进入系统章。公式不只用于介绍名词，应帮助预测修改序列长度、有效批量、精度或分片策略后会发生什么。

## 示例的三种状态

- **已执行的教学实验**：例如零依赖字符二元模型，结果仅证明其明确限定的演示目标。
- **语法检查过的教学代码**：说明算法或数据流；语法通过不代表依赖兼容、数值正确或训练有效。
- **尚未运行的 GPU/集群方案**：需要固定软件、模型、数据与硬件后验证。正文不将官方支持或示意配置描述为本书实测。

读者复制代码时，应先用最小样本验证数据和标签，再短跑、恢复、评估，最后扩大预算。每次引入新工具或新优化都要确认输入 token、损失掩码、归一化、参数更新与评测条件仍符合原来的训练合同。
